# Just Another TD — Design

## Elevator pitch

Классический tower defence, где башни **зарабатывают личность**. Не ты заранее выбираешь ветку апгрейда за золото — башня **совершает подвиги** в бою, и эти подвиги открывают ветви эволюции.

Рабочее имя механики: **Feats → Evolution** (Подвиги → Эволюция).

## Core loop

1. Ставишь базовую башню (мало типов на старте).
2. Башня копит статистику и прогресс по **Feats** (личным ачивкам).
3. Feat завершён → получаешь **Evolution Point**.
4. Ты направляешь очко по **ветви эволюции** этой башни (и иногда по общей «славе» карты).
5. Эволюция меняет роль башни: урон, контроль, поддержка, специализация по врагам — не просто +% чисел.

## Почему это интересно

- Каждая партия собирает **разный набор** эволюций в зависимости от того, *как* ты играл.
- Башни становятся персонажами: «эта лучница вынесла босса», «эта башня никого не упустила на своём участке».
- Выбор после подвига — драматический момент mid-run, сильнее обычного магазина апгрейдов.

## Feats (подвиги)

Feats — **у экземпляра башни**, не глобальные Steam-ачивки.

### Правила

- У каждой базовой башни есть пул из ~6–8 feats (общие + уникальные для типа).
- Прогресс виден при клике на башню (полоски / иконки).
- Завершение feat = короткий juice (звук, вспышка, метка над башней) + **1 Evolution Point**.
- За ран максимум **2–3 эволюции** на башню (чтобы не превратить всё в бесконечный snowball).
- Часть feats **взаимоисключающие** или закрываются после выбора ветки (роль зафиксировалась).

### Категории feats (чтобы не было только «нанеси больше урона»)

| Категория | Пример | Зачем |
|-----------|--------|--------|
| **Volume** | 40 убийств | Базовый прогресс |
| **Dominance** | ≥35% убийств волны, в которой башня участвовала | Твой пример «больше половины» — но смягчённо и по волне/сегменту, не за весь ран |
| **Precision** | 15 убийств подряд без промаха / без потери цели вне радиуса | Награда за хороший плейсмент |
| **Execution** | Добить 3 элитных / босса | Открывает «палач»-ветки |
| **Guardian** | Убить врага на последнем сегменте пути | Танк/контроль эволюции |
| **Support** | 20 assist (урон есть, килл забрала союзная) | Аура/дебафф ветки |
| **Underdog** | Сделать 25 киллов, будучи самой слабой по апгрейдам | Анти-снежный ком |
| **Specialty** | Убить 12 летающих / бронированных | Специализация |

### Важная правка к идее «>50% всех врагов»

Чистый глобальный «убила больше половины всех» почти всегда выигрывает первая сильная башня и убивает разнообразие.

Лучше так:

- **Wave Share**: доля убийств *среди башен, которые стреляли в эту волну*.
- Или **Lane Share**: доля на своём участке пути.
- Порог ~30–40%, не 50%+, и feat одноразовый (или с кулдауном на повторный tier).

## Evolution branches

После очка — **выбор из 2–3 веток**, не плоское меню из десяти пассивок.

Пример для лучницы (`Archer`):

```
Base Archer
 ├─ Marksman      — выше урон, уже конус, казнь низкого HP
 ├─ Ballista      — медленные тяжёлые снаряды, AoE по линии
 └─ Scout's Eye   — вскрывает невидимок, аура crit союзникам
```

Пример для морозной (`Frost`):

```
Base Frost
 ├─ Glacier       — сильнее slow, root на добивании
 ├─ Hailstorm     — меньше slow, больше AoE chip
 └─ Cold Snap     — взрыв при смерти врага в радиусе
```

Золото остаётся для **постройки и базовых тиров (T1→T2)**.  
Эволюция через feats — ** qualitatively другая форма**, не третий платный тир.

## Анти-снежный ком

Без этого система развалится:

1. Кап эволюций на башню (2–3).
2. Feats Underdog / Support тянут внимание на «слабые» башни.
3. Ветки **узкие по роли**: эволюция Marksman плохо чистит толпу — нужна вторая башня.
4. Некоторые feats требуют **разных** врагов/ситуаций → нельзя фармить одно и то же.
5. Опционально: после эволюции часть volume-feats закрывается, открываются feats нового тира.

## MVP scope

- Платформа: Windows, Godot 4.x, 2D.
- 1 карта, фиксированный путь.
- 3 базовые башни.
- 4 типа врагов + 1 босс.
- У каждой башни: 4 feats + 2 ветки эволюции (по 1 уровню).
- UI: панель башни с прогрессом feats и модалкой выбора эволюции.
- Красивый polish позже; сначала читаемый prototype.

## Open questions

- Сеттинг/визуал: сад / фонари / пепел / другое?

- Нужен ли «prestige» между ранами (мета-ачивки) или только внутри рана?

## Non-goals (v1)

- Редактор карт для игрока
- Мультиплеер
- 10+ типов башен
- Процедурная генерация карт
